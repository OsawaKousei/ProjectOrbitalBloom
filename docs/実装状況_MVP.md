# MVP実装状況

## 今回の実装単位：Stage 0〜2の操作基盤

ゲームルールは `GameCore/` に置き、Unreal Hostから入力を渡し、読み取り専用の
`RenderSnapshot`を取得する。CoreはC++17で独立ビルドでき、Unreal型を含まない。

実装済みソース：

- 60/120Hz固定ステップ、Player/Boss状態、移動フレーム。
- Followの距離維持と2軸周回、極付近でも破綻しないフレーム更新。
- ACTION/TACTICAL切替。停止中はゲーム時間を進めず、カメラ・UIは更新する。
- Player/Boss Orbitとズーム。
- Ghost Anchor、レイ上の深度調整、確定、Converge中の回避、Fixed到達、Follow復帰。
- 移動平面、到達方向のプレビュー、距離、アンカー状態の表示。
- 実時間・ゲーム時間・停止時間・停止区間・アンカー操作・移動距離の記録。
- 状態変更イベントの時刻とアンカー情報。完全なリプレイ記録は未実装。

## デザイン反映

ユーザー指定の `ビジュアル／UI デザインガイドライン.md` を今回の見た目の基準にする。
MVP設計書の暗背景指定に対し、低情報量・コントラストを維持したブルーグレーの
明るい背景から試す。シアンの自機・操作情報、細線、円環の移動平面、ダイヤ形の
Converge、十字のFixedを使用する。赤は配置不可の表示に限定する。

作成・保存したアセット：

- `/Game/MVP/Art/M_Player`：シアンのUnlitマテリアル。
- `/Game/MVP/Art/M_Boss`：淡色のマテリアルインスタンス。
- `/Game/MVP/Art/M_Sky`：低彩度ブルーグレーの背景インスタンス。

これは操作検証用の初期表現であり、最終VFX品質の達成を意味しない。
弾幕段階ではアンバー／マゼンタ系の弾と警告リングを分けて追加する。
射撃・Straightアンカーなど、ガイドラインに例示されたMVP外の機能は追加しない。

## Editor検証の再開手順

1. プロジェクトのC++モジュールがロードされていることを確認する。
2. `Tools/create_movement_study.py` をEditorのPythonで実行する。
   これはネイティブWorldFactoryで検証用マップを作り、GameModeを指定して保存する。
   開いているレベルは切り替えず、既存の検証用マップも上書きしない。
   スクリプトは構文検証済みだが、Editorでの実行は未検証。
3. 未保存の作業を保護したうえで `/Game/MVP/Maps/L_MovementStudy` を開く。
4. PIEで上記の操作を試し、停止中のSIM時刻固定とアンカー遷移を確認する。
5. 出力ログの `LogOrbitalBloom` と画面を確認し、問題を修正する。
6. 起動マップを設定する。現時点では未作成のマップへ設定を向けないため、
   `DefaultEngine.ini` の起動設定を変更していない。
